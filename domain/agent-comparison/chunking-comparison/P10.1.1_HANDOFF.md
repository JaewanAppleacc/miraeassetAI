## E. Sibling collapse 전후

- raw-flat(C, top-100 funnel) top-20 기준: 문서당 unique parent 수는
  같은 top-20 슬롯 20개 중 평균 5.90개가 **동일 parent sibling에게 낭비**됨
  (`mean_sibling_crowded_slot_count_at_20 = 5.90`, 즉 top-20의 약 30%).
- crowded-out sibling의 **96.3%가 TABLE_ROW** — 표 형태 문서(홀딩 보고서 등)의
  같은 표 안 여러 row가 서로 top-k 자리를 놓고 경쟁한 것이 crowding의 지배적
  원인이다.
- **document diversity cap(≤4/document)**을 적용하자 항목당 평균 26.47개
  group이 제외됨(top-100 collapsed 리스트 전체 기준). 다수의 Gold 다중-slot
  항목이 **같은 문서 안 서로 다른 4개 초과의 parent(표/섹션)**에 근거를 두고
  있어, cap이 실제로 필요한 근거를 밀어냈다.

## F. parent 1536→1024 효과 (동일 top-30 funnel, B vs C)

- B(parent=1536): Recall@10 = 0.700
- C(parent=1024): Recall@10 = 0.726 (**+0.026**, PARENT_SIZE_1536_DEGRADATION
  원인 확인됨 — parent를 작게 줄이는 것 자체는 순수하게 도움이 되었다)

## G. parent-aware 검색 효과 (동일 top-100 funnel, C vs D)

- C(raw-flat): Recall@10 = 0.688
- D(parent-aware): Recall@10 = 0.602 (**-0.086**, 기대와 반대 방향)
- sibling collapse는 crowding을 줄였지만(위 E 참고), document cap=4가
  동일 문서 내 5번째 이상 관련 evidence를 근거 부족 없이도 밀어내면서
  순손실이 더 컸다.
- 질문유형별로도 일관됨(NUMERIC_LOOKUP n=57: A 0.948 → C 0.737 → D 0.637;
  NARRATIVE_MULTI_DOC n=22: 0.985 → 0.905 → 0.826) — 우연이 아니라 구조적
  패턴이다.

## H. table row crowding 분석

- crowded-out sibling 596건 중 574건(96.3%)이 TABLE_ROW — 별도 원인
  `TABLE_ROW_CROWDING` triggered=true로 확정.
- `GOLD_LOCATOR_SCORING_MISMATCH`는 triggered=false (node_hit-locator_hit
  gap이 Fixed=0.000, D=0.030으로 임계값 0.05 미만 — row/col 채점 자체의
  결함은 아니다).

  - → 3개 중 2개(청크 수, RSS) 초과 → 조건 충족

**결과: `HIERARCHICAL_ELIMINATED_AFTER_PARENT_AWARE_RETEST`**

메인 101건 실행에서는 latency/RSS를 Hierarchical-1024 구성에 대해 별도

(`scripts/p10.1.1-determinism-and-latency-check.mjs`). 이는 "결과를 본 뒤
규칙을 변경"한 것이 아니라 이미 고정된 규칙에 필요한 입력을 완성한 것이다.
