## 7-3  Evidence Selector가 병목인가 — **그렇다**

gold 140건을 Case로 분해(A0, top-16 문맥 기준):

| Case | 건수 | 의미 |
|---|---:|---|
| A — gold가 top-20 밖 | 36 | Retrieval 문제 |
| A2 — top-20엔 있으나 top-16 밖 | 3 | context_k 문제 |
| **C — top-16 안에 있는데 selector가 못 고름** | **92** | **Agent layer 개선 후보** |
| D — selector가 실제로 지목 | 9 | 정상 |

**문맥 안에 있는 101건 중 selector가 지목한 것은 9건(8.9%)**. 남은 92건은 LLM 발췌에는
들어가지만 "이 근거가 이 slot의 답"이라는 매핑이 없다. 현재 selector가 slot당 1건만 고르고,
지표가 없는 질문은 상위 3청크의 첫 줄만 쓰기 때문이다.

## 7-8  실험 우선순위 판정

### MUST TEST
- **Evidence Selector 개선** — 문맥 안 101건 중 9건만 지목하는 구조. 가장 싸고(LLM 불필요)
  효과가 직접적이다. 다만 이 지표(selector 지목률)가 실제 답변 품질에 얼마나 기여하는지는
  HyperCLOVA X 실호출로만 확정된다.

### MAY TEST
- A2 heading+paragraph — ctx@16 +0.0143. 문맥 +8% 비용. 단독으로는 근거 약함.
- gold 라벨 검수 후 재측정 — AMBIGUOUS 60건이 지표를 왜곡하고 있어, 검수 뒤 숫자가 크게 달라질 수 있다.

### DO NOT TEST
- dense full retrieval / bge-m3 top-100 / 이름만 다른 dense reranker / Kiwi 계열 반복 /
  A3·A4 table-row 재실험 / stage1_k 추가 sweep / 전체 코퍼스 확장.
  전부 이번 또는 직전 라운드에서 기각됐거나(개선 없음·regression), latency 벽에 갇혀 있거나,
  현재 의사결정을 바꾸지 못한다.
