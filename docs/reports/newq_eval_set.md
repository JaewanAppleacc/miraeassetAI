# seed 밖 평가셋 — 팀 공통 Gold v0.2 형식

작성 2026-08-31 · LLM 호출 0회 · 비용 0원

## 왜 만들었나

팀 공통 평가 하니스는 seed 25문항만 채점한다. **"seed 밖 질문에서 무너지나"를 아무도
재지 못한다.** DEV_TUNE 25문항으로 계속 튜닝하면 그 세트에 맞춰지는데, 그걸 확인할
바깥 기준이 없다.

그래서 우리가 만든 18문항을 **같은 형식**으로 바꿨다. 팀 하니스가 그대로 읽는다.

## 어떻게 만들었나

- 코퍼스에서 **gold25가 안 건드린 기업** 10곳(한미반도체·에코프로비엠·두산에너빌리티·
  두산퓨얼셀·한국항공우주·대우건설 등)의 실제 공시를 읽고 질문을 썼다.
- 값은 **원문에서 그대로** 가져왔다. 근거 위치는 팀 계약과 같은 형식으로 만든다:
  `{doc_id}/{접수번호}.xml#node={노드번호}` — 스크립트가 실제 문서를 스캔해 노드를 찾는다.
- **우리 시스템이 맞히는지와 무관하게** 만들었다. 정답지를 우리 출력에 맞추지 않았다.

## 구성 (18문항 · 근거 슬롯 19개)

| 유형 | 문항 | 내용 |
|---|---|---|
| 정답 있음 | 12 | 계약금액·투자금액·자기자본대비·계약기간·해지금액/사유 등 |
| 함정 | 6 | 코퍼스에 없는 기업 / 범위 밖 연도(2015) / 공시에 없는 정보 / 모호한 질문 |

함정 6개가 핵심이다. **"모른다"고 답하는지**를 재는 문항이 seed 세트에는 거의 없다.

## 검증

팀 자신의 계약 검증기(`validateEvaluationGoldV02`)로 확인 — **18문항 전부 유효**.
route_policy 필수 같은 제약도 그 검증기가 잡아줘서 맞췄다.

## 우리 시스템 채점 결과 (LLM 없이)

| 항목 | seed 25문항 | **새 18문항** |
|---|---|---|
| 계약 통과 | 25/25 | **18/18** |
| metric_pass | 36 | **47** |
| evidence | 5 PASS / 26 FAIL | **14 PASS / 5 FAIL** |
| value | PASS 4 / FAIL 2 | **PASS 9 / FAIL 2** |
| unit | 6 PASS / 3 FAIL | **11 PASS** |
| answerability | 12 PASS | **13 PASS** |

seed 세트보다 점수가 높은 이유는 우리가 잘해서가 아니라 **Gold 필드 이름이 규칙적이기
때문**이다(seed 세트는 문항 전용 이름이 181종). 그래서 이 세트는 "시스템 비교"에
쓰기 더 공정하다 — 이름 맞추기 싸움이 아니라 값 맞추기 싸움이 된다.

## 팀에서 쓰는 법

```bash
# 1) 자기 Agent 서버를 띄운다 (GET /answer 지원 필요)
# 2) config의 gold_path를 이 파일로
node scripts/run-evaluation-harness.mjs run/newq_config.json
```

파일: `data/eval/newq_gold.v0.2.jsonl` · 생성 스크립트: `scripts/build_newq_gold_v02.py`
설정 예시: `docs/reports/data/newq_harness_config.json`

## 주의

- 이 세트는 **seed 세트를 대체하지 않는다.** 일반화를 재는 보조 기준이다.
- 우리가 만들었으므로 **우리 시스템에 유리할 수 있다.** 다른 사람이 문항을 추가하면
  그 편향이 줄어든다 — 형식이 같으니 그냥 줄을 더하면 된다.
