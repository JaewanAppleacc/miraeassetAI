                             +LOW-confidence KURE 재정렬

D LINE_WINDOW+DENSE_OFF      line-window 12/8 · 메타필터+BM25-only
                             (=B에서 dense OFF)

해석: A↔C, B↔D는 쌍 내 dense 관련 설정 외 조건 동일을 유지하되
  최종 결과는 완성 스택 간 system-level 비교로 보고한다.
  C↔D도 서로 다른 청킹·토크나이저·후보 생성을 포함한 두
  metadata-filtered BM25-only 스택의 system-level 비교이며,
  청킹 하나의 인과효과로 단정하지 않는다.
주 판정: LOW(확정 조건 ≤2) all-required-slots-found count
  · conditions.py 사전 계산+SHA 고정 · LOW<10이면 frozen
  paraphrase set(정확히 20문항·salt 정렬·독립 검수) 절차
게이트: Hard safety(provenance·locator 치명 0 — slot-match
  청크만 검사) → Quality(hard-safe arm 최고 대비 −0.01)
동률: 최고값 기준 FINAL_TIE_SET → dense-off 우선 →
  C·D 동률 시 안전성→latency p95→peak RSS→배포 의존성→D
승자 = PROVISIONAL_WINNER → 동결 → DEV_CHECK(47) one-shot
  통과 시에만 FINAL_RETRIEVAL_CORE_SELECTED · HOLDOUT 봉인
메타필터에 Gold 유래 정보 사용 발견 시 실험 전체 INVALID
Late Expansion은 4-arm 후보가 아님 — PROVISIONAL_WINNER 산출물
  위 별도 X0/X1 실험, 코어 선택 점수와 혼합 금지,
  현 후보는 Fixed locator 호환이라 A/C 승리 시 한정
※ 판정 규칙 전문(1~21번)은 동결된 vFINAL 원문을 따른다 —
  byte 수정 금지, 변경은 vFINAL 21번 절차로만
